# Capability boundaries

This public source candidate implements safe adoption/discovery, candidate-bound bounded context and repository-scoped local-first Memory through the Pi package, plus selected no-model regression mechanics. Its supported guidance follows idea/conversation → spec → executable → build → verify → delivery without requiring Project Brain, Obsidian, an MCP vault, or a parallel documentation brain. Acceptance of a reviewed source identity, independent critique and actual post-import clone verification are separate gates; no historic acceptance is inherited.

The integration tracer checks source/provenance, an actual installed Pi local-package resolver with no model/client construction, explicit safe adoption, discovery, core status/validation and unchanged relocated package bytes. Exactly one package skill and one Razr extension are permitted; prompts, themes, and context files remain absent. Loading does not adopt or authorize writes.

The selected public suite covers adoption refusal/idempotence/separation/relocation, loader refusal/no-adoption, synthetic contract preflight, core-materialized synthetic work inspected read-only, stale-generation refusal, exact delivery commit identity even when excluded-input changes preserve the source digest, source/provenance and privacy boundary refusals, deterministic immutable-Git-tree M03 context selection (including dirty/untracked refusal, mutate-and-restore isolation, and foreign/stale Memory omission), bounded private Memory ledgers whose live source identity cannot be replaced by a constructor digest and whose cooperative lock has checked but explicitly non-race-proof same-UID limits, and collector test/subcase behavior. Core approval in a fixture uses explicitly synthetic metadata and never represents a real human decision. No lifecycle state is hand-written.

The shipped M07 GitHub delivery helper (`packages/razr-pi/scripts/github-delivery.py`) provides explicit `snapshot`, read-only `read`, and separately-authorized `create` operations. It binds repository, base/head branches and full base/head SHAs, and source digest; uses host-pinned authenticated GitHub observations; and reports bounded non-atomic read metadata. No-check output is an observed `none` result, not proof that tests ran or passed. Review/comment/request/status collections returned through the bounded provider path are explicitly marked incomplete because `gh pr view` supplies no pagination metadata; review threads use bounded pagination.

Create can leave a remote side effect after transport or response loss. Exact recovery and candidate-bound close compensation report `created-but-unverified`, compensation unavailable, or compensation uncertain rather than implying no mutation. Create requires separate explicit authority and does not merge, deploy, force-push, mutate Razr lifecycle state, launch critics, infer approval, or implement a PR factory. Final human PR review remains mandatory.

General review dispatch, local-history admission and automatic PR/factory capabilities are deliberately absent. Explicit unmatched-attempt recovery remains a narrow evidence operation, not a dispatcher. Excluding dependencies does not prove portable replacements. No historical test aggregate, review outcome or model allowance transfers here. Runtime core commands beyond the public adapter's scope remain present for lifecycle authority, not as adapter execution authority. Existing legacy brain/vault hooks are compatibility inputs to migrate or ignore explicitly, never hidden requirements.

M09 hardens its mechanical boundary with streamed independent output bounds, process-group cleanup, executable-link refusal, an explicitly propagated per-launch end-to-end deadline without shared mutable deadline state, explicit fresh-context argv, pre-claim duplicate refusal, core-read generation/ordinal/candidate fences, a final pre-start candidate check, descriptor-rooted no-follow evidence, permanent STARTED root/path consumption with integrity-bound fail-closed claim-journal loss, and additive restart-validatable late session binding. These controls do not make Herdr telemetry Razr state. M08 exercised: distinct caller/target panes, target-worktree binding, two non-overlapping Luna/medium slices, an interrupted attempt with no inferred completion, replacement, fresh candidate-bound bounded reviews, and Memory stale/revalidation. A corrective work item records candidate binding, bounded review acceptance, then delivery linkage without rewriting the earlier chronology. That source-bound campaign observation is recorded in `docs/campaigns/razr-pi-next.md`; it does not turn host telemetry into authority or supply final critics.

Missing prerequisites and declared fixtures are failures, not passing skips. Pattern scanning and hashes are not confidentiality certification, approval authentication or a sandbox. Memory uses restrictive local permissions and broader secret-like rejection, but those heuristics cannot detect every secret or make Memory a confidentiality boundary; its advisory sibling lock coordinates cooperative processes and does not exclude hostile same-UID pathname replacement. Review all source before publication. Tests run from an allowlist-only materialized tree without historical data; that is not a freshly cloned published repository. Actual post-import clean-clone execution, exact-source review, fresh independent Technical/Contract critique and human final review remain required. No publication or factory work is authorized by passing tests.
